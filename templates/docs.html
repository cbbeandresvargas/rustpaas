Documentación Oficial de RustPaaS

RustPaaS es una plataforma como servicio (PaaS) diseñada para compilar y hospedar aplicaciones web escritas en Rust (o cualquier lenguaje que compile a un binario standalone) de manera eficiente. Todo en un solo archivo binario con 0 dependencias externas pesadas.

1. Deploy Manual (Curl)

Puedes desplegar una aplicación directamente enviando el binario compilado al API del PaaS. Asegúrate de compilar tu aplicación para la misma arquitectura del servidor (generalmente x86_64-unknown-linux-gnu).

curl -X POST https://paas.tudominio.com/api/deploy \
  -F "name=mi-app" \
  -F "binary=@./target/release/mi-app"

Al hacer esto, RustPaaS buscará un puerto libre, configurará el subdominio mi-app.paas.tudominio.com, y arrancará el proceso inyectando variables de entorno automáticamente.

2. Deploy Automatizado (GitHub Actions)

La mejor manera de usar RustPaaS es mediante CI/CD. Añade este archivo a tu repositorio en .github/workflows/deploy.yml:

name: Deploy to RustPaaS
on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: x86_64-unknown-linux-gnu
      - run: cargo build --release
      - run: |
          curl -X POST "https://paas.tudominio.com/api/deploy" \
            -F "name=mi-app" \
            -F "binary=@./target/release/mi-app"

Con esto, cada vez que hagas push a la rama main, GitHub Actions compilará tu aplicación y la desplegará en tu servidor en cuestión de segundos.

3. Almacenamiento S3 Integrado

RustPaaS tiene un motor S3 embebido (basado en s3s). Cuando despliegas una aplicación, se crea automáticamente un bucket para ella. Tu proceso recibe las siguientes variables de entorno que puedes usar con cualquier cliente de S3 (como `aws-sdk-s3` en Rust):

S3_ENDPOINT="http://localhost:9000"
S3_BUCKET="bucket-mi-app"

No se requieren claves de acceso (access key / secret key) porque el motor local confía en las peticiones internas, aunque puedes configurar credenciales en el cliente S3 para que no falle la inicialización (usa cualquier string).

Nota: Puedes subir archivos desde la UI del dashboard, o usando tu propio código dentro de tu aplicación.

4. Bases de Datos & Backups

Para bases de datos transaccionales, recomendamos fuertemente usar SQLite. RustPaaS garantiza que tu aplicación correrá en la misma máquina virtual y el mismo sistema de archivos.

Tu aplicación recibe la variable:

DATABASE_URL="sqlite://./mypaas-data/apps/mi-app/data/app.db"

Conéctate a esa ruta usando SQLx o rusqlite. Desde el dashboard, puedes presionar el botón Descargar Backup (DB); RustPaaS hará un volcado seguro VACUUM INTO en vivo sin interrumpir tu aplicación y te enviará el archivo .db para que lo guardes.

5. Scale-to-Zero (Auto-suspend)

Para maximizar la cantidad de aplicaciones que puedes hostear en un VPS pequeño (ej. 1GB de RAM), RustPaaS monitorea el tráfico.

Si una aplicación no recibe ninguna petición HTTP en 10 minutos, el proceso hijo se termina (enviando SIGKILL o SIGTERM). Su estado en el dashboard cambiará a Suspended.

En el momento en que alguien visite el subdominio de tu aplicación, el proxy inverso retendrá la petición web, arrancará tu binario nuevamente, esperará a que el puerto responda, y le pasará la petición de manera transparente (tarda ~10ms en una app Rust optimizada).
